# Инструкция по установке


### 1. Установить необходимые программы

Откройте PowerShell и выполните установку git:
```powershell
winget install --id Git.Git -e --source winget
```
Другой вариант: установить git по ссылке: https://git-scm.com/install/windows

Теперь установите пакетный менеджер Python uv:
```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

Установите Google Chrome, если он ещё не установлен. После установки закройте
PowerShell и откройте его снова.

### 2. Скачать репозиторий

```powershell
cd "$env:USERPROFILE\Documents"
git clone https://github.com/ordenmeny/cdp_parsing.git MegamarketControl
cd MegamarketControl
```

### 3. Создать файл настроек

Получите у администратора токен доступа. Затем из папки `MegamarketControl`
создайте файл .env:

```powershell
New-Item .env -ItemType File
```

Откройте .env (например, через блокнот) и впишите пять строк, подставив полученный токен вместо `<токен>`:

```dotenv
PARSER_REMOTE_API_URL=http://10.0.4.69:8001
PARSER_REMOTE_API_TOKEN=<токен>
PARSER_REMOTE_API_TIMEOUT=600
PARSER_BROWSER_HOST=127.0.0.1
PARSER_BROWSER_PORT=51112
```

Проверьте, что получилось:

```powershell
Get-Content .env

Проверьте доступность сервера:

```powershell
Invoke-WebRequest http://10.0.4.69:8001/docs -UseBasicParsing
```

В результате должен появиться статус `200`.

### 4. Подготовить программу

Выполните из папки `MegamarketControl`:

```powershell
uv sync --locked
```

Команда обязательна при первой установке и может занять несколько минут.

Интерфейс собирать не нужно: при каждом запуске программа сама скачивает его
с сервера и запоминает в
`%LOCALAPPDATA%\MegamarketControl\frontend`. Заново он скачивается только
после того, как интерфейс обновят на сервере.

## Каждый запуск программы

### 1. Запустить специальное окно Chrome

Откройте PowerShell и выполните:

```powershell
$chrome = @("$env:ProgramFiles\Google\Chrome\Application\chrome.exe", "${env:ProgramFiles(x86)}\Google\Chrome\Application\chrome.exe", "$env:LOCALAPPDATA\Google\Chrome\Application\chrome.exe") | Where-Object { Test-Path $_ } | Select-Object -First 1
& $chrome --remote-debugging-port=51112 --user-data-dir="$env:LOCALAPPDATA\chrome-profiles\megamarket-12" --disable-blink-features=AutomationControlled --no-first-run --no-default-browser-check
```

Не закрывайте открывшееся окно Chrome во время работы.

Проверить Chrome можно командой:

```powershell
Invoke-RestMethod http://127.0.0.1:51112/json/version
```

Если появилась информация о версии Chrome, браузер готов.

### 2. Запустить приложение

Откройте ещё одно окно PowerShell. Перейдите в ту же директорию и запустите веб-сервер:

```powershell
cd "$env:USERPROFILE\Documents\MegamarketControl"
uv run uvicorn megamarket.api.app:app --host 127.0.0.1 --port 8000
```

Не закрывайте это окно PowerShell во время работы.

### 3. Открыть интерфейс

Откройте в браузере:

```text
http://127.0.0.1:8000
```

## Как пользоваться

### Собрать товары

1. Откройте вкладку **Обработка**.
2. Введите обычный поисковый запрос, например `makita`.
3. Нужно собрать несколько запросов — нажмите **Добавить запрос** и впишите
   следующий, например `iphone 17`. Полей может быть до 20; лишнее убирается
   крестиком справа.
4. Нажмите **Запустить и скачать Excel**.
5. Не закрывайте специальное окно Chrome.
6. После завершения Excel-файл скачается автоматически.

Запросы обходятся по очереди в одной вкладке, а на выходе получается **один
файл** со всеми ними. Строку с товаром, который нашёлся сразу по нескольким
запросам, файл содержит один раз. Колонка **Запрос** показывает, откуда взялась
строка, — по ней удобно фильтровать прямо в Excel.

Колонки идут в таком порядке: Ссылка, Название товара, Бренд, ID карточки,
Описание товара, Цены, Рейтинг, Продавец, Ссылка на продавца, ID продавца на
маркетплейсе, Юр. Лицо, Юр. Адрес, ИНН продавца, ОГРН, seller_phone,
seller_email, link. Дальше идут служебные: Наличие и Запрос.

**ID карточки** — число, посчитанное от ссылки на карточку. Один и тот же товар
у одного продавца всегда получает один и тот же идентификатор, в том числе в
разных запусках и файлах, поэтому по нему можно связывать строки из разных
таблиц. В файле он лежит текстом: числом Excel показал бы пятнадцать цифр как
`1,14492E+14`, а при правке клетки округлил бы их.

**ID продавца на маркетплейсе** берётся из той же ссылки — это номер магазина,
под которым он известен Megamarket.

**Рейтинг** берётся из карточки в выдаче; у товаров без отзывов клетка пустая.

**Юр. Лицо, ИНН продавца, ОГРН, seller_phone, seller_email** приходят из базы
продавцов. Они появляются там после проверки продавца, поэтому у тех, кого ещё
не проверяли, клетки пустые — прогоните вкладку **Обработка → Проверить
продавцов**, и в следующем отчёте реквизиты будут. **Ссылка на продавца**
подставляется только у продавцов со статусом **Корректный**: у остальных она
пока лишь предположение.

**link** — ссылка на изображение товара.

**Бренд**, **Юр. Адрес** и **Описание товара** не заполняются: колонки в файле
есть, значений в них нет. Описание живёт только внутри карточки товара, а
заходить в неё программа не должна. Имя файла складывается из
запросов: `makita-iphone_17-samsung_s24`; для длинного списка оно сворачивается
до первого запроса и числа остальных.

Запросы обходятся строго по очереди: полностью первый, затем второй и так
далее. Если прогон оборвётся на втором запросе — первый уже собран и попадёт
в файл вместе с тем, что успел дать второй. В таком случае программа скажет
об этом: «Прогон прервался: обработано запросов 1 из 3».

Если во время сбора закрыть вкладку с выдачей, оставшиеся запросы выполнены не
будут, но собранное к этому моменту всё равно попадёт в файл.

### Если сайт попросит подтвердить, что вы не робот

Megamarket иногда показывает страницу «Запросы с вашего устройства похожи на
автоматические». Программа это видит и **ждёт вас**: в окне PowerShell появится

```text
Сайт решил, что запросы автоматические. Решите проверку в окне Chrome — жду до 300 сек.
```

Пройдите проверку в том самом окне Chrome, которое открыли для работы. Как
только выдача вернётся, сбор продолжится сам, а в лог придёт «Проверка
пройдена, выдача вернулась». Ничего перезапускать не нужно.

После проверки страница обычно открывается там же, где вы остановились.
Карточки, собранные до неё, не теряются и в файл второй раз не попадут.

Если за отведённое время проверку не пройти, программа остановится и сохранит
собранное. Время меняется в `.env`:

```dotenv
PARSER_CAPTCHA_TIMEOUT=300
```

### Проверить продавцов

1. На вкладке **Обработка** выберите Excel-файл.
2. Укажите количество продавцов.
3. Нажмите **Проверить и скачать файл**.

Обработанный файл скачается с тем же именем. Ссылка останется только у продавца
со статусом **Корректный**. Если не выбирать файл, программа проверит продавцов
в базе без скачивания Excel.

На вкладке **Продавцы** доступны просмотр, поиск, фильтрация и редактирование.
Отметьте одного или нескольких продавцов флажками и нажмите
**Проверить выбранных**, чтобы запустить проверку только для них.
Повторно проверять можно продавцов с любым статусом, в том числе
**Некорректный**: при успешной проверке статус изменится на **Корректный**.
Перед повторной проверкой предполагаемая ссылка пересчитывается по текущим
правилам Megamarket: `embeq.store` откроется как `/shop/embeqstore/`,
`Перекрёсток` — как `/shop/perekrestok/`, `ХОБОТ` — как `/shop/hobot/`.
Повторная проверка безопасно дополняет данные: новые непустые реквизиты заменят
старые, но пустой ответ сайта не удалит уже сохранённые ОГРН, ИНН, контакты,
официальное название или рейтинг.

### Объединить отчёты

1. Откройте вкладку **Объединить**.
2. Нажмите **Выберите Excel-файлы** и отметьте нужные. Выбирать можно в
   несколько заходов из разных папок — список дополняется, а не заменяется;
   повторно выбранный файл в списке не задвоится. Лишний убирается крестиком.
3. Нажмите **Объединить и скачать**.

Файлов должно быть от 2 до 50, каждый не больше 50 МБ. Готовый файл скачается
под именем вида `all-megamarket-<дата>.xlsx`.

Колонки сопоставляются по названию, а не по порядку, поэтому объединять можно
и файлы с разным набором колонок: недостающие клетки останутся пустыми. Строки
на повторы **не проверяются** — один и тот же товар из двух файлов попадёт в
результат дважды. Так объединение работает быстрее; если дубли мешают, уберите
их в Excel («Данные» → «Удалить дубликаты»).

Объединение идёт на вашем компьютере: файлы никуда не отправляются, Chrome и
сервер для него не нужны.

## Завершение работы

1. Дождитесь окончания текущей операции.
2. Нажмите `Ctrl+C` в окне PowerShell с запущенным приложением.
3. Закройте специальное окно Chrome.

## Обновление кода программы

Откройте PowerShell и выполните:

```powershell
cd "$env:USERPROFILE\Documents\MegamarketControl"
git pull
uv sync --locked
```

После обновления запускайте программу обычным способом. Интерфейс обновится
сам при первом запуске.

## Если программа не запускается

Проверьте сервер:

```powershell
Invoke-WebRequest http://10.0.4.69:8001/docs -UseBasicParsing
```

Проверьте Chrome:

```powershell
Invoke-RestMethod http://127.0.0.1:51112/json/version
```

Если обе проверки работают, закройте ранее запущенную копию программы через
`Ctrl+C` и снова выполните команду запуска приложения.

### Страница не открывается

При запуске программа скачивает интерфейс с сервера. Посмотрите на окно
PowerShell с запущенным приложением:

- `Не удалось обновить интерфейс с сервера` вместе с `Открыт интерфейс,
  скачанный ранее` — сервер недоступен, но программа работает на прошлой
  версии интерфейса. Проверьте сервер по инструкции выше.
- `Интерфейс недоступен` — сервер недоступен, и скачанной копии ещё нет. Так
  бывает при первом запуске без связи с сервером. Дождитесь доступности
  сервера и запустите программу снова.
